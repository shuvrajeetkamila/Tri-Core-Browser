# Known limitations and blockers

**Status date:** 2026-10-12. Use the current build report/test report for newer Windows CI outcomes.

## Graphics (major feature gap)

- **NVIDIA DLSS Super Resolution and Frame Generation: NOT IMPLEMENTED / NOT TESTED.** No official production Streamline/DLSS runtime, NVIDIA-provided NGX identifier/accepted engine metadata, native renderer integration, or compatible physical hardware result is present. DLSS-SR and DLSS-G are distinct native integrations; detecting an NVIDIA GPU never activates either control. Streamline framework source and proprietary feature binaries have separate licensing/distribution terms; the reviewed NVIDIA RTX SDK license is dated 2023, so exact terms for any future release must be rechecked before distribution.
- **AMD FSR1: bounded game-owned WebGPU source path; current runtime evidence incomplete.** The bundled scene owns its lower-resolution target, EASU/RCAS compute path, and visible-canvas presentation, with no CPU readback in the processing loop. Hosted run [38287627583](https://github.com/shuvrajeetkamila/Tri-Core-Browser/actions/runs/38287627583) passed Windows build, packaged smoke, and Level A evidence validation, but its per-stage report was not inspected. The optional aggregate WebGPU result is therefore **UNKNOWN** (accepted as either PASS or safe SKIPPED); current EASU/RCAS dispatch and visible-output evidence are **NOT VERIFIED** and are not claimed. Physical-GPU/AMD-vendor validation remains **NOT RUN**; see the [FSR1 WebGPU acceptance ledger](FSR1_WEBGPU_ACCEPTANCE_LEDGER.md).
- **`capturePage()` PNG → native D3D12 FSR1: diagnostic-only.** The packaged Level A validator in run 38287627583 passed its required screenshot/PNG-to-WARP diagnostic gate. The separate native-harness run [38287627651](https://github.com/shuvrajeetkamila/Tri-Core-Browser/actions/runs/38287627651) passed one synthetic D3D12-WARP EASU+RCAS frame and basic nonblank/non-bilinear output checks. Both are software-only, not live WebGPU integration, zero-copy, arbitrary-page support, or physical-GPU evidence; artifact image contents were not inspected.
- **Hybrid/Auto: no general-page FSR activation.** The scene-specific FSR path is excluded from automatic selection for ordinary tabs. DLSS is unavailable; standard pages stay on Chromium; WASM is a runtime diagnostic and never upscales.
- **No arbitrary website upscaling.** `WebContentsView` does not expose arbitrary page targets or a supported compositor/swap-chain bridge. Electron 44.7.0's experimental offscreen shared-texture API is a candidate only; its upstream E2E spec is macOS-arm64-only, and this app's Windows capture/import/presentation remains unverified. WebGPU video/image import and Windows Graphics Capture exist as scoped APIs, but neither supplies a tested whole-page processing path. Arbitrary WebGL/WebGPU pages/games, protected/DRM playback, cloud streaming and external applications are unsupported/not tested; no injection, memory inspection, DRM bypass, or Chromium security bypass is used.
- **No performance/image-quality claims.** WebGPU `performance.now()` timing is queue-completion wall time, not GPU timestamp. The screenshot helper's capture/readback/helper timings are diagnostic, not game FPS. Output dimensions or simple image sanity metrics alone do not establish better quality or faster rendering.

## Browser feature gaps

- Three simultaneous browser cores with per-core tabs are provided; this is not a full single-window tab strip. Each core is capped at 20 tabs.
- No extensions, password manager, account, bookmark/history sync, private/incognito mode, tab groups, browser profiles UI, or cross-device sync.
- Bookmarks/history/home-page preference are stored in one local JSON file in Electron's user-data folder. There is no export/import or automatic cloud backup.
- The downloads list is for the current application session. Downloads go to the Windows Downloads folder; they are not automatically executed.
- Site permissions are denied by default. There is no per-site permission UI or certificate exception UI.
- The browser is not a custom Chromium build. It inherits Electron's Chromium update cadence and security lifecycle; rebuild and publish promptly when Electron/Chromium updates are required.

## Platform, build and release

- Windows x64 is the target. The Linux Arena container cannot launch or locally package the Windows app. Latest hosted run [38287627583](https://github.com/shuvrajeetkamila/Tri-Core-Browser/actions/runs/38287627583) on source `ef83a60` built and size-validated the Windows executable, passed the packaged smoke and Level A evidence validator, and uploaded the explicitly unverified executable candidate plus diagnostics. Portable distribution assembly was skipped; this artifact is not release-certified. The summary-writing step passed, but its per-stage report body was not inspected.
- The app is unsigned. Windows SmartScreen may warn and Windows has no verified publisher identity for this binary.
- The current hosted run's optional aggregate WebGPU status is **UNKNOWN**: its successful validator allows either a real optional `PASS` or safe `SKIPPED`, and the per-stage report was not inspected. EASU/RCAS dispatches, stage metrics, and visible-canvas output are not claimed. The independent D3D12 WARP harness [38287627651](https://github.com/shuvrajeetkamila/Tri-Core-Browser/actions/runs/38287627651) passed its software-only one-frame test; physical GPU remains **NOT RUN**. Level B was skipped on the push event. The optional `https://example.com/` runtime probe may be **BLOCKED** if the hosted runner/network cannot reach it; certificate checks are never bypassed.
- Full npm audit on the current lockfile reports 8 moderate findings and 0 high/critical findings. They converge on `sprintf-js@1.1.3` through `roarr`/`global-agent`/the builder's `@electron/get` chain. npm currently proposes a semver-major `electron-builder@26.5.0` change; no forced downgrade, unverified override, or dependency update was applied. CI audits the full lockfile and fails on high/critical findings. See `docs/TEST_RESULTS.md` for the safe-remediation decision.
